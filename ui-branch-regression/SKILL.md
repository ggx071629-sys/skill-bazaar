# 真实界面操作分支回归

沿实际用户操作检查「看到了什么、操作后发生了什么、状态是否符合预期」。覆盖单位是有明确前置状态的操作分支；打开一个页面不代表该页所有分支通过。

## 1. 确认环境、对象与操作范围

读取工程约定、相关任务记录、页面入口和已有验证结果，确定本次是检查、修复后复验，还是检查并修复。未指定环境时从当前工程与已打开入口判断并说明；只有存在会改变执行结果的歧义时才补问。

- 从实际界面核对应用或网址、当前路由、运行包或构建、账号及数据模式。开发工具已登录不证明应用已登录，离线演示包也不证明后端已接通。
- 使用当前可用且获准的浏览器或应用工具，先读取其操作文档；定位当前活动页面，避免隐藏历史视图、旧标签或旧构建造成误判。静态检查可辅助定位，但不能代替真实界面证据。
- 沿用用户已授权的环境、数据和动作。指定虚构数据或离线模式时继续使用；会触发未授权真实支付、发布、消息发送或数据写入的步骤，停在该动作前并继续其他分支，不因回归测试扩大授权。
- 保留已完成的有效证据。没有新增改动或疑点时不为凑齐一轮演示重复全量测试；共享组件变化则根据实际引用确定受影响页面。

工具不能观察目标界面时，说明具体缺口，继续源码或其他可执行检查，相关视觉与交互保持未验证。遵守当前工具的访问限制，不把某次环境限制泛化为所有浏览器或平台都不可用。

## 2. 按风险列出实际分支

从路由、现有任务、组件使用和已发现问题确定范围。用户要求全页面时先列出页面清单，再标明各页适用分支；只查指定流程时不要扩大成全产品审计。根据产品已有规则判断预期，不自行增加确认弹窗、校验规则或新业务流程。

用现有测试清单或简短记录保存「页面/入口、前置状态、动作、预期、实际结果、证据、状态」。优先覆盖本次变更和容易丢状态的分支，不机械展开所有组合。合并同类页面或抽样时说明依据与未覆盖差异，不能据此声称全分支验证。

| 涉及内容 | 重点分支 |
| --- | --- |
| 表单校验 | 空值、实际约束边界、无效输入、纠正后重试；错误位置与焦点可见，纠正后错误解除。 |
| 编辑与离开 | 未改动返回、已改动返回、继续编辑、明确放弃；输入与选择保留或丢弃符合既有约定。 |
| 选择控件 | 当前值、有效改选、取消改选；核对实际值与选择态，不只确认选择器已打开。 |
| 提交或确认 | 合法输入后的已授权操作、结果展示与返回；检查确认区是否可见、后续状态是否真实更新。 |
| 导航与恢复 | 从正常入口进入、相关深链接直达、无上一页时返回、离开再进入；筛选、草稿和滚动状态按约定恢复。 |
| 布局与动态状态 | 用户指定尺寸、相关窄屏、长文本、键盘及弹层；滚动、提示淡出或异步回调须按时间顺序实际观察。 |

## 3. 实际执行并取得证据

每个分支先核对前置状态，按真实路径操作，再读取当前界面与状态。需要判断排版、遮挡、选择态或提示可见性时查看实际画面；DOM、辅助功能树或应用状态用于核对数值与目标，不把截图存在本身当作判断已完成。

特别检查：

- 校验错误能否在用户当前视野中发现，纠正、继续编辑后输入是否仍在；不只验证错误字符串出现。
- 返回确认、提交结果和主要操作是否在长页、键盘或弹层中被遮挡，用户是否能继续操作。
- 点击是否真正激活了目标；离屏控件可能只被滚入视野。根据当前观察确认结果，不因工具超时、滚动或定位成功盲目重复提交。
- 保存、放弃或返回后，列表、详情、原始值或草稿状态是否符合预期。成功提示不能单独证明持久化；离线演示只验证演示行为，不声称真实后端写入成功。
- 页面切换后，旧定时器、异步结果或旧确认状态是否影响新页面。只有变化相关或已有疑点时检查，不要求每页制造此类状态。

原生选择器或特定输入无法可靠操作时，将该分支记为受阻；可以继续验证取消等独立动作，不能用值未变化的操作冒充有效改选。前置状态不成立时先修正定位或记录受阻，不能拿错误页面的结果计覆盖。

涉及长页确认区、原生选择器、环境混淆或动态验证时，按需阅读 [references/cases.md](references/cases.md)。示例不规定其他产品的交互方式。

## 4. 按授权修复并定向复验

只检查时输出问题与证据。已要求修好时，对有依据的问题作必要修改，保留现有视觉方向、业务规则和无关工作；不把走查变成重设计。修改前记录复现路径与读者或用户影响。

源码修复按项目要求补有意义的回归，验证状态保留、导航目标、可见性或失效回调等实际行为，不以匹配 CSS 文本或提示文案代替行为验证。运行相关检查与工程必需检查，已有有效结果可以复用；新失败、新改动或未解决疑点才扩大范围。

确认目标环境已加载修复，再按原路径实际复验，并检查受影响的邻近分支。例如修复返回确认后，继续编辑和放弃退出都应按其既有规则核对；共享组件修复按实际使用情况选择受影响页面。测试通过与真实界面复验分别记录；无法完成后者时保留缺口，不填写「已验证修复」。

恢复本次改变且已知原值的测试状态，仅处理本轮创建的可识别测试数据，不清理用户既有内容。结束时将界面留在适合用户查看或继续操作的位置；不要为重新截图重跑成功的提交动作。

## 5. 汇报覆盖与剩余问题

分支采用清楚的状态：

| 状态 | 含义 |
| --- | --- |
| 通过 | 在标明环境中实际完成该分支，观察结果符合预期。 |
| 失败 | 已实际执行并观察到与既有预期不符的结果，附复现路径与影响。 |
| 受阻 | 缺少前置条件、授权或可靠观察/操作能力，写明停在哪一步。 |
| 未执行 | 已在本次范围中列出，但尚未走查。 |

修复后保留原发现和复验结果，不抹掉初始失败；只改源码尚未复验时说明修复待验证。统计时每个独立分支只计一次，重试和修前修后不重复增加覆盖数。页面数、已执行分支数、已修复问题数与未验证项分别表述；没有完整分母时不用完成率或「全部通过」。

交付以本次结果为主：检查环境与范围、实际发现及修复、关键画面或记录位置、通过与受阻/未执行分支、仍需处理的事项。清楚区分源码检查、H5、模拟器与真机证据，不将某一端的通过扩展到未测环境。沿用项目已有记录；小任务可直接在对话交付，不强制建设新的测试系统。
