# 界面分支判断案例

以下为归一化的判断示例，不是已执行的测试或其他项目的默认交互规范。重点看前置状态、实际动作与结论范围。

## 长页面的返回确认藏在屏外

**前置与动作**：修改长表单底部的虚构输入，触发返回，当前产品约定应询问是否保留编辑。

**观察**：确认区已进入 DOM，但视野仍停在表单底部，用户看不到后续操作。

**判断与复验**：这是确认可见性问题，不能因查到提示文字就通过。按原有交互让确认区可见，再验证「继续编辑」保留输入、「放弃」按约定返回且不保存；重进页面时不残留上次确认。保留原有风格，不据此替所有页面增加弹窗。

## 原生选择器打开不等于有效改选

**前置与动作**：页面当前选择 A，打开原生选择器，准备改成 B；工具只能打开和取消，不能可靠选择 B。

**判断**：有效改选分支受阻，不能继续用 A 验证后宣称切换成功。若能实际取消并观察值仍为 A，可单独记录取消分支通过；也不能把确认区不变当成 B 的选择态错误。

## H5 正常不代表模拟器或真机通过

**材料**：H5 的选择态正常，微信模拟器中样式不同；开发工具已登录，但当前运行包仍使用演示数据和游客项目身份。

**判断**：分别记录 H5 与模拟器观察，只修有证据的差异。工具账号、项目身份、应用登录和后端连通是不同状态；换一个项目标识不证明真实登录及数据库写入已接通。未测真机保持未验证。

## 无历史记录的直达入口

**前置与动作**：正常从详情进入编辑页时取消可返回；直接打开编辑页深链接，没有上一页，取消后仍停在编辑页。

**判断与复验**：先核对产品的返回约定。若应回对应详情，可补充该场景的返回处理，同时复验正常入口。不要用统一回首页覆盖有效历史栈，也不要凭测试者习惯自拟新导航规则。

## 旧回调影响新页面

**前置与动作**：触发确认区的延迟滚动，立即离开并重新进入同一路由。

**观察与复验**：旧回调在新页面触发跳动。修复后按同一顺序复验，同时检查正常确认仍可见。必须辨认当前页面实例，单纯等待旧回调执行完再截图无法覆盖此问题。

## 滚动提示的代码检查通过，画面仍未验证

**材料**：模型测试支持「首次进入显示、滚动增强、停止后淡出」，但工具未能读取目标界面画面。

**判断**：代码或模型检查通过，实际动态体验未验证。不能拿 CSS 数值、生成的 HTML 或一张静态图证明三个时段均正常，也不能把受阻分支删除后称全部通过。

**可执行时的复验**：在同一实际页面观察进入、滚动、停止三个阶段，按现有时序等待并核对表现；再检查短页面不产生无意义提示。访问受限时记录当前限制，继续其他可执行检查，不绕过工具约束。
