# A03 能力真实性

登记在 Capability Ledger（`../coverage.md` 账本 B），不要写入 System Object Ledger。写缺陷 finding 前须已读 `../finding.md`。一条能力**只有一个** Result。

## 判定维度

每条至少确认：Declared、User Entry、Implementation、Reachable、Entry Class。

Entry Class：Canonical（正式产品 IA）· Alternate · Internal · Legacy · Debug · None。

## 优先级（自上而下，命中即停）

1. 证据不足 → **未判定**  
2. Declared=yes 且链完整、真实可达 → **Verified**（不是 finding）  
3. Declared=yes 且链缺失/损坏/不可达 → **Phantom**  
4. Declared=no 且 Canonical 用户入口真实可达 → **Hidden**  
5. Declared=no 且 Alternate/Internal/Debug/Legacy/bypass 入口可达 → **Shadow**  
6. 实现仍在，但当前无有效入口/调用链 → **Zombie**

README 仍声称 Export、代码有 ExportService、但无当前入口 → **Phantom**（声明优先），Related → A17 stale implementation。不要同时给 Phantom+Zombie。

## Hidden vs Shadow

- **Hidden** = 没宣传的**正常**产品能力（设置里能走到的 CSV 导出）。  
- **Shadow** = 正式产品面之外仍活着的能力（`/debug/reindex`、旧 CLI、绕权限的直调）。

## Result → Finding

Capability Result 与 Failure Type 是两个维度，不新增 F15/F16。

| Result | Finding |
| --- | --- |
| Verified | 不出 finding |
| Phantom | **必须**至少一条 finding（除非明确记 Informational observation）。按实际失效选 F01 Missing / F02 Broken / F08 Unreachable 等 |
| Zombie | **必须**至少一条 finding，默认 F09 Zombie |
| Shadow | **必须**至少一条 finding，默认 F10 Shadow |
| Hidden | 仅未声明且无负面控制面影响 → 只登记 Result，不强制 finding；若违反产品/控制面预期 → 按具体失效出 finding |
| 未判定 | 不出缺陷 finding |

一条能力一个 Result。文档用词 → A16。仓库处置 → A17。禁止每个能力都硬找出毛病。
