# 分阶段计划生成与维护

让接续的 Agent 能快速找到「有哪些任务、做到哪里、下一步做什么」，只加载当前工作必需的内容。计划负责执行组织；功能范围和正确性以已确认要求、设计及适用 Spec 为依据。

## 1. 确定本次任务与依据

先区分用户要求的是生成或修订计划、执行已授权阶段并维护计划，还是只核对进度。只要求计划时不启动产品实施；更新计划也不自动授权计划中列出的任务。

读取适用的项目指令、现有计划和本次相关设计。项目有 Harness 时按其入口读取适用规则；没有则直接工作，不要求先建设 Harness。已知目标分计划时直接定位，不必通读所有阶段和归档。

确认本次交付范围、阶段顺序、已完成工作、关键依赖与验收来源。沿用仍有效的批准和已有设计，不把规划中的方案写成已采用，也不把「实现前端」改成重新设计界面。只有缺失信息会改变当前计划或实施边界时才问，其余可独立工作继续推进。

## 2. 使用主计划、分计划和归档

沿用已有位置、编号与链接，不为套模板迁移整个计划。新计划未指定路径时放在 `build-plan/`；多个计划并存时按主题建独立目录。参考结构：

```text
build-plan/<主题>/
  README.md
  phase-a.md
  phase-b.md
  completed/
    phase-a/
    phase-b/
```

| 载体 | 保留的内容 |
| --- | --- |
| 主计划 | 总体范围与进度、分计划链接；每阶段的完成数量、状态、当前或下一任务、关键阻塞 |
| 阶段分计划 | 阶段目标、范围与限制；完成数量、阶段状态；每项任务的编号、名称、状态、关键前置和已完成归档路径 |
| 分计划中的当前任务 | 简短执行清单、必要输入定位、阻塞、下一步、完成条件及适用验收引用 |
| 已完成任务归档 | 本任务实际改动、关键决定、验证结论及证据位置、失败与复验、仍适用的限制 |

分计划是任务状态的依据，主计划维护对应摘要。不同阶段各有分计划，不合成长文；分计划可把 60–80 行作为精简目标，必要信息较多时允许超出。当前任务就地维护，不另拆一份执行文件，不逐轮追加对话日志。未来任务保留清单、关键前置与完成条件引用，实施细节到执行时再展开。

业务规格留在原设计或 Spec，以具体章节引用，避免复制出第二套规则。只在追溯某项事实时读取对应归档；仍生效的限制和未解决阻塞留在活动分计划，不能只藏进历史。

## 3. 生成或调整计划

从已确认的交付结果拆出任务，再依据真实依赖组织阶段。用户指定的前端先行、沿用设计、完成某阶段停下等要求应反映在任务和阶段边界中，不预设所有项目采用同一开发顺序。

- 每项任务有可检查的结果和必要前置；验收引用已有适用条件，不额外发明 Gate、审批或整套测试门槛。
- 编号稳定、引用可定位，依赖无循环；不得把未授权后续阶段列为当前阶段的隐性实施范围。
- 新任务标为未开始；已有工作按实际交付和证据保留状态，不把整份计划重置，也不凭已有文件认定完成。
- 重排、拆合或取消任务时保留变更依据与旧编号去向。取消项单列，不计入已完成；不通过删除未完成项制造完成率。
- 建立归档位置即可，不预填完成记录。只生成计划的请求，生成完后给出当前或下一任务并收尾。

## 4. 接续、验证与归档

接续时核对当前任务、实际工作和适用证据，不只相信旧摘要。尊重用户指定的顺序；没有指定时，选择前置已满足且在本次范围内的任务。有效批准不因换任务或接续对话而失效，无需逐项重复确认。

任务状态至少区分以下含义；项目已有等价名称时保留原名：

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚未实施 |
| 进行中 | 正在推进，仍有交付工作未完成 |
| 阻塞 | 必要前置、资源或决定缺失，记录具体原因和解除条件 |
| 未验证 | 交付已实施，但必要验收未运行、未通过或缺少证据 |
| 完成 | 本任务交付齐备，适用验收已满足，有可追溯的结果 |

验证按任务适用要求进行。已有证据在变更范围和输入仍适用时可说明理由后复用；受影响或缺失的部分再核验。不把类型检查代替真实接口、浏览器或业务验收，也不为纯文档任务强制运行全量应用测试。

保留失败、错误、未运行与修复后的复验结论。工具未配置是工具状态；是否阻塞任务取决于已采用的完成条件，不直接写成测试失败或通过，也不靠修改完成条件关闭任务。

任务完成后，将过程与证据归档到 `completed/<阶段名>/`，核对归档路径，再同步任务行、阶段计数、主计划摘要和下一任务。未完成时，必要现场与下一步留在当前任务区，不放进完成归档。写入前重读相关段落，保留共享工作区的无关修改。

## 5. 处理依赖与阶段边界

跨阶段前置冲突先判断：它是真实实施依赖、可直接引用的已采用设计，还是任务编排错误。有明确依据、且不改变已确认范围或顺序的局部修正可直接记录并同步；需要新增范围或改变用户指定边界时，只询问这个决定，同时推进其他独立任务。

达到用户指定的停止点就收尾；后续阶段保持其真实状态。不因任务计数全部完成就自动关闭阶段或整体 Spec：仍需核对该范围已有的阶段验收条件。局部完成不能升级为整个项目、日常可用性或上线已经验收。

## 6. 核对与报告

保存后核对本次涉及的内容：任务及范围没有遗漏；编号、依赖和链接有效；完成项有对应归档与适用证据；主分计划的数量、状态、阻塞和下一步一致。有效阻塞没有随归档消失，未来任务没有因调整计数被误标完成。

计划结构、链接或计数检查只证明文档相应部分一致，不证明产品已实现或验收通过。

结束时简短报告计划入口、本次生成或完成的范围、实际验证、当前或下一任务，以及仍有效的阻塞和未完成项。已完成授权范围就收尾，不为消除范围外待办继续扩展任务。
