# 产品决策变更同步

把一个已确认决定及其必要影响同步到项目资料，保留尚未决定的事项。交付是可核对的文档修订或差异分析；不以增加功能、替用户补齐业务规则为目标。

## 1. 确定本次变更与证据

以用户本次明确要求确定变更，读取目标文档、项目指令与必要上下文。已有足够依据时直接定位，不强制回放整段历史或要求用户重新讲述。

逐项辨认：

- **已确认**：用户明确采纳的要求及边界，包括「暂用」「首期」「本轮」等限定。
- **候选或建议**：讨论过但未采用的方案，或用户明确要求先保留的候选。
- **后续或待定**：尚需明确的规则、范围与验证事项。
- **已替代**：被后续明确决定修订的旧方案。

必要时在工作中整理「原决定 → 新决定 → 适用范围 → 确认依据」；不强制为每次小改动新增决策日志。只核实会影响本次同步的版本、平台、人群、生效时间或阶段范围；范围不同的表述可以同时有效。

区分确认采用、计划实施、已实现与已上线。确认一项设计不证明实现或发布，不能直接把面向现有用户的说明改成已支持该能力。

识别用户指定的基准与项目现有权威记录，不默认 README、较新的文件时间或任一段对话天然优先。本次用户明确要求改变的旧决定可在相应范围内替代；其他文档和历史消息用于核对相关依据与影响。

用户的简短「可以」结合紧邻上下文判断，不能扩大为接受之前所有备选。需要跨对话核对时，读取足够的原始用户消息与上下文确认相关决定，不只依赖标题、摘要或其他助手的断言；无需无差别遍历所有历史。较新的助手建议不自动替代较早的用户决定。

出现冲突时先按确认依据、适用范围与明确替代关系梳理，能消除的差异无需再请用户决定。仍无法判断且会改变修改结果时，只询问冲突点；其他独立、明确的变更可以继续处理。无法读取某段对话时，说明未核对范围；本次明确指令已足够支持的修改可以继续，不宣称完成了未读对话的核对。

## 2. 查找受影响的表述

从已知资料及其引用出发，用文件搜索和关键词搜索定位相关内容；同时查新旧名称、同义词、旧状态和入口描述，不只替换原句。

依据变更检查相关维度即可，不要求每次扫描全部仓库：

| 变更涉及 | 重点检查 |
| --- | --- |
| 导航、功能归属 | Tab 清单、页面职责、模块表、入口来源、层级与共用页面 |
| 完成、审核或权限 | 操作前置条件、状态、成功与失败说明、个人与公开内容边界 |
| 计费、权益或激励 | 付费说明、订单入口、可用权益、免费范围、失败和后续调整说明 |
| 分类、主题或统计 | 分类层级、主题归属、计数对象、分母与进度说明 |
| 本轮范围或完成状态 | 文档开头状态、完成标准、后续事项、摘要与交接说明 |
| 文件或章节名称 | 文档索引、相对链接、章节锚点和正文引用 |

检查主文档与维护同一结论的 README、摘要、流程示例等。没有直接关系的代码、配置和其他技能不属于默认修改范围。用户明确限定只改某个文件时，其他发现只报告；受影响载体不可编辑时记录未同步位置，不另建一份影子文档冒充同步完成。

## 3. 区分修正与新决定

将影响分成三种，按需要内部记录或向用户列出：

1. **直接变更**：用户明确要求修改的内容，按要求更新。
2. **必要连带修正**：新决定在同一适用范围内必然造成的矛盾，随本次同步修正。不同版本、平台或生效阶段的差异不直接归为漂移。
3. **需要另行决定的影响**：存在多种合理处理方式，保留为待定或提出具体问题。例如成就库成为独立 Tab，并不必然要求删除首页快捷入口。

必要修正限于消除已确认决定带来的矛盾，不从单项变更补出新功能、计费方式、统计口径或页面，也不将候选升级为上线承诺。存在多种合理处理方式时保留待定，不以“保持一致”为理由替用户选择。

需要具体判断示例时，按需阅读 [references/cases.md](references/cases.md)，其中包含导航、审核、候选、付费、阶段收尾、版本差异和修改范围案例。案例中的产品选择不是其他项目的默认要求。

## 4. 更新当前表述并保留真实历史

用户已要求更新时，在明确范围内直接编辑，不额外设置一轮确认。若用户只要求讨论或只读比较，则输出建议或差异，不擅自保存为已采纳结论。

- 沿用现有文件、格式与术语，更新权威记录及直接受影响的摘要、表格、状态与流程示例。
- 同一适用范围的当前方案保持一致，版本或平台例外保留其限定。旧方案若留在当前方案段落中，应注明已被替代；原始决策日志、访谈、历史截图、研究事实与发布历史不重写成新方案，必要时按原有体例追加说明或指向新决定。用户明确要求纠正原始记录时按其范围处理。
- 候选和待定保留其状态。只关闭已解决的问题，未解决的连带影响明确列出，不填入自拟默认值。
- 阶段收尾依据约定范围。用户确认某一阶段完成后，可以标明该范围已完成，将范围外事项留在后续阶段；不据此声称整个产品、实现或效果已验证。
- 创建新对话、发布、发送外部消息或实现代码不是同步文档的默认附带动作。

共享工作区可能有其他修改。落笔前读取目标段落，保留无关变更，不用旧文件快照覆盖整份文档。

## 5. 核对与收尾

检查实际保存后的文档：

- 本次决定是否在所有已检查的当前表述中一致，旧名称、旧状态或旧入口是否仍有未标明的残留。
- 直接修改与连带修正是否有确认依据，候选是否被误写为正式需求。
- 目录、页面表、状态说明和后续事项是否相互符合，是否误把规划写成已实现或抹掉有效的版本例外；涉及的本地文件链接、章节锚点是否有效。
- 修改是否仅覆盖相关文档，没有覆盖他人无关工作。

工具检查只证明对应范围；文字断言、链接校验和格式检查不证明产品逻辑正确或运行功能有效。不为普通文档同步强制运行应用测试或进行全项目审计。

完成后简短说明：修改了哪些文档、同步了什么决定、检查了什么，以及仍需决定或未能核对的事项。若本次变更已同步，剩余待定规则不应使本次任务无限延长；也不要把局部同步描述为整个项目已完全一致。
