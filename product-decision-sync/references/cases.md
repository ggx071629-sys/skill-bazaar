# 变更影响案例

这些是从产品讨论中抽取的示例，用来练习区分直接修正、必要连带修正与待定事项，不是其他项目的默认产品要求。只在遇到对应歧义或核对同步质量时阅读。

## 取消完成审核

**原记录**：提交材料 → 等待审核 → 审核通过后解锁；个人页含审核记录；公共人数被描述为核验通过人数。

**用户决定**：首期用户确认完成即可解锁；以后公开展示内容时再考虑展示审核。

**应同步**：

- 当前解锁流程和必要状态去掉等待完成审核，个人页去掉对应查询入口。
- 分清个人解锁与后续公开展示审核，不能把后者又放回解锁前置条件。
- 删除或修正「公共人数代表平台核验」的当前表述，将新统计口径列为待定。

**不能顺带决定**：照片是否必填、公共人数去重方式、未来审核标准或所有个人内容默认公开。

## 成就库独立进入底部导航

**原记录**：四个 Tab，成就库通过首页进入；首页有独立成就库入口模块。

**第一次决定**：成就库作为主体，放在中间，出发负责组合搭配与定制。

更新导航数量、顺序、页面归属及相关摘要。首页入口是否仍保留需要另行判断，不能擅自删除；也不能据此确定启动时默认打开成就库。

**后续决定**：取消首页独立成就库入口模块，首页保留产品介绍、开始或继续体验、成就推荐。

此时才删除独立模块，更新首页模块表、详细章节、导航摘要和 README，检查是否还保留旧的四模块清单。「查看更多」如果只是切换 Tab，不计为新增二级页面；是否提供该跳转按本次决定标注。

## 收集作为主题，分类与内部候选仍保留

**用户决定**：常规分类仍需要；收集作为长期主题，城市、动物、植物等先保存为候选方向；六个内容分类也仅为候选。

**应同步**：

- 区分内容分类、长期主题与主题内部候选方向。
- 检查候选表标题、正文和摘要，避免把每个候选写成已上线的独立顶层主题。
- 保留常规成就的内容设计职责，不把整个库改成收集玩法。

**仍待定**：选择哪些候选、收集范围、收集项与成就的对应关系、进度分母与图鉴展示。主题方向已确认不等于这些规则已确认。

## Agent 定制确认付费

**用户决定**：Agent 定制需要付费，其他收费细节未定。

**应同步**：相关服务入口和说明不得继续承诺 Agent 免费。

**仍待定**：价格、支付位置、按次或订阅、失败处理、调整次数、手动搭配是否免费。只有后续用户分别确认时才进一步更新，不从「付费」二字补出整套权益规则。

## 页面框架阶段收尾

**约定范围**：明确主页面的内容、职责、直接关联的二级页面与复用关系，不包含 UI 或完整业务流程。

**用户决定**：本轮已完成，剩余规则进入后续阶段。

**应同步**：在文档顶部标明本轮完成范围，修正仍要求重做已确认框架的后续事项，将统计、支付、记录等细化问题留在后续阶段。

**完成检查**：既不能因尚有后续规则就拒绝结束本轮，也不能宣称整个 App、全部流程或产品效果已经完成或验证。未获创建授权时，不自动新建下一阶段对话。

## 不同版本和平台的差异

**原记录**：当前 v1 仍通过人工审核；已发布的 v1 用户帮助和发布历史对此有说明。

**用户决定**：v2 的个人记录改为自行确认完成，微信小程序暂时仍沿用 v1 流程。

**应同步**：在 v2 设计中更新完成流程，并保留版本和平台限定；当前能力说明区分已发布与规划状态。

**不应改动**：不能把 v1 发布历史、小程序规则或当前用户帮助统统替换成新流程。这里不同范围的规则并不矛盾；仅在现有依据和用户指令仍不足以确定文档适用范围时，再询问该文档应描述哪个版本。

## 只读比较与单文件修改

**请求一**：「比较这段讨论和文档，先不要改。」只输出有证据的差异与影响，不保存新决定。

**请求二**：「只更新页面文档，不改 README。」更新指定文件；如 README 仍描述旧决定，报告该未同步位置，不越过文件范围。

**请求三**：「按我现在明确的新决定更新；旧对话暂时无法打开。」若本次指令足以确定新决定，就同步可确认的部分，说明没有核对旧对话，不要求用户重新批准已经明确的变更。

若相关共享文档没有编辑权限，报告该载体的未同步范围；不创建同名替代文档或宣称全局一致。
